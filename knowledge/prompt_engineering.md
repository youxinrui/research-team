# Prompt 工程与结构化输出

Prompt 工程的目标是让模型稳定地产生可用的输出。一个可维护的 prompt 通常包含四部分：角色设定、任务目标、约束条件、输出格式。角色和任务要具体，约束要可检查，输出格式要明确到字段级别。

Few-shot 示例能显著提升格式稳定性。示例应覆盖典型输入和边界输入，并保持与真实请求相同的结构。示例过多会占用上下文，通常 2 到 5 条即可。

结构化输出有两种常见实现。第一种是在 prompt 中要求返回 JSON，并在应用层解析和校验；这种做法依赖模型遵循指令，需要处理解析失败、字段缺失和类型错误。第二种是使用 JSON Schema 约束或 function calling，让模型按给定 schema 返回结构化结果，可靠性更高，也便于做类型校验。

Function calling 的流程是：应用把可用工具及其参数 schema 传给模型，模型返回工具调用请求，应用执行工具并把结果回传给模型，模型再决定下一步。工具描述要写清用途、参数和返回格式；工具执行需要有超时、重试和权限控制。

prompt 也需要版本管理和评测。修改 prompt 后应在固定评测集上回归，比较通过率、格式错误率和成本，而不是只看单次输出是否顺眼。
