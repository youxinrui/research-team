# RAG 评测体系

RAG 评测分为检索质量和生成质量两层。检索层常用 Recall@K、MRR 和 nDCG：Recall@K 衡量前 K 个结果中是否包含标准答案，MRR 衡量第一个相关结果出现的位置，nDCG 还考虑排序位置和相关性等级。

生成层常用 Faithfulness 和 Answer Relevancy。Faithfulness 衡量回答中的陈述是否能被检索到的上下文支持，Answer Relevancy 衡量回答是否切题。Context Precision 和 Context Recall 则分别衡量检索上下文的准确性与覆盖度。这些指标的定义与 RAGAS 等框架保持一致，便于横向比较。

评测集需要人工标注或半自动构造。检索评测集是查询与标准片段的对应关系；生成评测集是问题、参考答案和可用上下文。评测集要覆盖正常、边界和应拒答三类情况，并保持一定规模，否则指标会饱和、失去区分度。

LLM-as-judge 可以降低标注成本，但需要固定评分 rubric、控制温度，并抽样人工复核。评测应纳入回归流程：每次修改检索策略、prompt 或模型后重新运行，比较指标变化，而不是只看单次演示效果。

超参数如融合权重和命中阈值，应在评测集上做网格搜索确定，并记录选择依据。线上还应监控拒答率、引用有效率和用户反馈，形成离线与线上结合的闭环。
