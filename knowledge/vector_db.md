# 向量数据库选型

向量检索的存储方案需要按规模、过滤需求、持久化和运维成本选择。小规模场景可以直接用 numpy 在内存中计算余弦相似度，零依赖、实现简单，适合 demo 和单机应用；数据量达到数十万条以上时，内存占用和检索延迟会成为问题。

Chroma 是轻量级向量库，API 简单，支持本地持久化和元数据过滤，适合快速开发和中小规模应用。pgvector 是 PostgreSQL 的向量扩展，可以直接复用现有数据库的事务、备份和 SQL 过滤能力，适合已经使用 Postgres 的团队。Milvus 面向大规模向量检索，支持分布式部署、多种索引和水平扩展，但运维复杂度更高。

索引类型影响召回率和延迟。HNSW 基于图结构，查询快、召回高，但内存占用较大；IVF 先聚类再检索，内存更省，但需要调参且召回略低。选择索引时要结合数据规模、延迟目标和内存预算。

选型时还应考虑过滤条件。很多业务需要按租户、时间或标签过滤，支持元数据过滤的向量库能减少后处理。最终建议是：demo 用本地索引，中等规模用 Chroma 或 pgvector，大规模再考虑 Milvus，并把向量库封装成可替换接口。
