# Docker、CI 与部署

Docker 把应用及其依赖打包成可移植镜像。Python 应用通常使用多阶段构建：第一阶段安装依赖并构建，第二阶段只复制运行所需文件，减小镜像体积。基础镜像建议使用 slim 版本，例如 python:3.12-slim，并避免以 root 用户运行。

docker-compose 用于编排多个服务。一个典型的 AI 应用包含后端、前端和数据库：后端暴露 API，前端由 nginx 或后端静态托管，数据库使用命名卷持久化。环境变量和密钥通过 env_file 或 secrets 注入，不要写进镜像。

CI 负责在每次提交时执行检查。GitHub Actions 可以配置两个任务：后端运行 pytest 和静态检查，前端安装依赖并执行构建。测试和构建都通过后再允许合并，能避免把坏代码带到部署环境。

Linux 部署常见方式是 systemd 管理进程，nginx 做反向代理和 TLS 终止。应用需要健康检查接口、结构化日志、优雅退出和资源限制。密钥应放在服务器的环境变量或密钥管理服务中，并定期轮换。

部署后还要关注可观测性：请求量、错误率、延迟分位数、模型调用成本和限流情况。没有这些指标，线上问题很难定位。
